# C++ Code Review Master

**组合式 C++ 代码评审方案** — 整合静态分析、安全编码规范、C++编程规范、C语言编程规范、经验与教训、高风险函数检查、多轮迭代评审。

> **版本 2.1.0** — 新增C语言编程规范、经验与教训，评审维度从 13 个扩展到 14 个。

## 14 个评审维度

| # | 维度 | 关注点 |
|---|------|--------|
| 1 | 内存安全 | 泄漏、悬垂引用、野指针、double-free、use-after-free、初始化 |
| 2 | 未定义行为 | 未初始化、数据竞争、整数溢出、类型双关、精度溢出 |
| 3 | RAII/所有权 | 构造/析构顺序、智能指针、初始化列表、虚析构 |
| 4 | 性能 | 不必要拷贝、临时对象、虚函数开销、容器选择 |
| 5 | 安全编码 | 注入防护、溢出、路径遍历、加密、随机数、防重放 |
| 6 | 高风险函数 | 线程不安全函数、缓冲区溢出函数、信号不安全函数 |
| 7 | 并发安全 | 锁粒度、死锁、atomic、线程不安全全局状态 |
| 8 | 现代 C++ | constexpr、string_view、format、Concepts、override |
| 9 | 代码规范 | 命名、头文件组织、格式、include guard |
| 10 | 函数设计 | 参数、返回值、const 正确性、assert |
| 11 | 类与对象 | 成员顺序、初始化列表、虚析构、职责单一 |
| 12 | 输入验证 | SQL 注入、XSS、CSRF、路径遍历、文件上传 |
| 13 | 日志与错误处理 | 敏感信息泄露、审计日志、统一错误处理 |
| 14 | C语言编程规范 | 关键字陷阱、内存管理规则、函数设计原则、文件结构规范、预处理陷阱 |

## 支持的评审场景

| 场景 | 命令 | 说明 |
|------|------|------|
| 单文件评审 | `/cpp-review <file.cpp>` | 评审指定 C++ 文件 |

| 深度学习 | `/cpp-review --explain` | 附带详细解释的评审 |

## C语言编程规范核心内容

《C语言深度解剖》提供了7个章节的详细开发规则、开发经验与开发教训：

### 1. 关键字规则（第1章）
- **auto/register/static/extern**：存储类型关键字使用规则
- **const/volatile**：类型修饰符陷阱与优化
- **sizeof**：运算符的正确使用与陷阱
- **struct/union/enum**：复合类型定义规则
- **typedef**：类型别名的最佳实践

### 2. 符号与注释规则（第2章）
- 注释的规范写法与陷阱
- 运算符优先级与结合性陷阱
- 位运算符的常见错误

### 3. 预处理规则（第3章）
- 宏定义的陷阱与替代方案
- 条件编译的正确使用
- 文件包含的规范与优化

### 4. 指针和数组陷阱（第4章）
- 数组名与指针的区别
- 多维数组的访问与传递
- 指针运算的边界检查

### 5. 内存管理规则（第5章）
- **野指针防护模式**：定义即初始化、malloc后检查、free后置NULL
- **内存泄漏检测**：malloc/free配对、资源释放顺序
- **内存对齐优化**：结构体对齐、跨平台兼容性

### 6. 函数设计原则（第6章）
- **函数入口校验模式**：参数有效性检查、返回值处理
- **结构体压缩参数模式**：减少函数参数数量
- **错误处理统一模式**：错误码定义与传播

### 7. 文件结构规范（第7章）
- 头文件与源文件组织
- 模块化设计原则
- 接口与实现分离

### 开发经验与开发教训
- **开发经验**：指针安全模式、函数入口校验模式、结构体压缩参数模式
- **开发教训**：结构体成员指针未初始化、malloc大小错误、字符串拷贝遗漏结束符
- **陷阱**：sizeof陷阱、宏定义陷阱、运算符优先级陷阱

## 安全模式

默认启用**安全模式**，每步需用户确认：

```
✅ 读取代码、运行只读命令、Spawn subagent 分析、报告问题
⚠️  修改文件、git commit、Spawn Fixer（需用户同意）
❌  未经同意修改代码、自主运行多轮修复、自主提交
```

## 使用示例

### 1. 评审当前 git diff
```bash
/cpp-review --diff
```

### 2. 评审指定文件
```bash
/cpp-review src/utils/memory_pool.cpp
```

### 3. 评审 PR 并自动修复
```bash
/cpp-review --pr --fix
```

### 4. 全量项目评审
```bash
/cpp-review --full
```

### 5. 仅安全编码检查
```bash
/cpp-review --security
```

## 局限性

- 并发限制：最多 3 个 subagent 并行
- 最大轮次：10 轮（防止无限循环）
- 代码外传：使用本地分析模式时不向外部发送代码
- 评分主观：评分算法基于规则，实际效果需根据项目调整
- C语言规则：C语言编程规范主要针对C语言，部分规则在C++中可能不适用或已有更好的替代方案
