## 1. 内存安全（Memory Safety）

### 🔴 必须检查
- [ ] 是否有裸 `new[]` / `delete[]`？建议改用 `std::vector` 或 `std::unique_ptr`
- [ ] 是否存在悬垂指针（dangling pointer）？
- [ ] 是否存在 double-free？
- [ ] 是否有 use-after-free 风险？
- [ ] 内存分配 / 释放是否配对？（malloc/free 次数必须相等）
- [ ] 数组和动态内存是否赋初值？（防止未初始化内存作为右值）
- [ ] `delete` / `free` 后是否将指针置为 `nullptr`？（防止野指针）
- [ ] 是否有数组或指针下标越界？
- [ ] 结构体成员指针是否已初始化并分配内存？
- [ ] `malloc` 大小是否正确？（`sizeof(struct)` vs `sizeof(struct*)`）
- [ ] `malloc` 返回值是否检查了 NULL？
- [ ] 字符串拷贝是否预留 `\0` 结束符空间？
- [ ] 是否有 `malloc(0)` 使用？（不返回 NULL 但无法使用）
- [ ] 是否有返回指向栈内存的指针/引用？

### 🟡 建议检查
- [ ] 是否有 `std::auto_ptr`？（已废弃，应用 `std::unique_ptr`）
- [ ] 是否有 `malloc`/`free` 与 `new`/`delete` 混用？
- [ ] 异常安全性：资源获取是否使用 RAII？
- [ ] `malloc` 语句字节数和类型转换是否正确？
- [ ] `new[]`/`delete[]` 数组形式是否匹配？

## 2. 未定义行为（Undefined Behavior）

### 🔴 必须检查
- [ ] 变量是否在定义前使用？
- [ ] 定义变量时是否同时初始化？
- [ ] 是否访问了数组越界？（循环用半开半闭区间）
- [ ] 是否有符号整数溢出？（`int` 溢出会 UB）
- [ ] 是否有除零操作？
- [ ] 是否有空指针解引用？
- [ ] 是否有返回指向栈内存的指针/引用？
- [ ] 是否有有符号数溢出导致的死循环？（如 unsigned 循环变量 `i>=0`）
- [ ] 移位操作是否超过类型宽度或为负数？
- [ ] `getchar()` 返回值是否赋给了 `char` 类型？（应为 `int`）

### 🟡 建议检查
- [ ] 是否有数据竞争（data race）？
- [ ] 是否有类型双关（type punning）？应使用 `std::bit_cast`
- [ ] 移位操作是否超过类型宽度？
- [ ] `union` 使用是否涉及活跃成员之外的写操作？
- [ ] 是否有精度不够或溢出的数值计算？
- [ ] 是否有误差累积问题？

## 3. RAII / 所有权（Ownership）

### 🟡 建议检查
- [ ] 构造函数 / 析构函数顺序是否正确？
- [ ] 是否有成员初始化顺序问题？（按声明顺序初始化）
- [ ] `std::unique_ptr` 是否正确使用？（禁止复制，使用 `std::move`）
- [ ] `std::shared_ptr` 是否有循环引用风险？（使用 `std::weak_ptr` 打破）
- [ ] 锁的获取 / 释放是否配对？是否使用 `std::lock_guard`？
- [ ] 构造函数是否使用初始化列表？
- [ ] 多态类是否有虚析构函数？
- [ ] 构造/析构函数中是否调用了虚函数？（禁止）

## 4. 性能（Performance）

### 🟢 可选检查
- [ ] 是否存在不必要的拷贝？（传参应使用 `const T&` 或值语义 + `std::move`）
- [ ] 是否存在不必要的临时对象？
- [ ] 循环内是否有重复计算可以提取？
- [ ] 是否需要内联建议？（频繁调用的小函数）
- [ ] 是否使用了虚函数但可以静态派发？
- [ ] 容器操作是否高效？（`push_back` vs `emplace_back`）
- [ ] 是否选择了正确的容器？（`std::vector` 通常优于 `std::list`）
- [ ] 循环体内逻辑判断是否可移到循环外？

## 5. 安全编码（Security）

### 🔴 必须检查
- [ ] 是否有 `strcpy`/`sprintf`/`scanf`/`gets`？（缓冲区溢出风险）
- [ ] 是否有用户输入直接拼接到命令字符串？（命令注入）
- [ ] 是否有未验证的指针运算？
- [ ] 是否有硬编码的敏感数据？（密钥、密码、Token）
- [ ] 是否有路径遍历风险？（用户输入拼接到文件路径）
- [ ] 是否有 SQL 注入风险？（用户输入拼接 SQL）
- [ ] 是否有格式化字符串漏洞？（`printf(user_input)`）
- [ ] 是否使用安全随机数？（安全场景禁止 `rand()`）
- [ ] 是否有文件上传安全检查？（类型、大小、路径）
- [ ] 加密算法是否安全？（禁止 MD5/SHA1/DES/RC4 用于安全场景）

### 🟡 建议检查
- [ ] 整数操作是否做边界检查？（防止整数溢出绕过安全检查）
- [ ] 错误信息是否泄露敏感信息或系统信息？
- [ ] 是否有防重放机制？（重要操作加随机数/时间戳）
- [ ] 是否有数据完整性校验？（签名机制）
- [ ] 框架和组件版本是否安全？
- [ ] `memcpy` 的源和目标是否可能重叠？（应用 `memmove`）
- [ ] `memset` 清零敏感数据是否可能被优化器消除？

## 6. 高风险函数（Dangerous Functions）

### 🔴 禁止使用
- [ ] `gets` → 替换为 `fgets`
- [ ] `strcpy` → 替换为 `strncpy` / `std::string`
- [ ] `sprintf` → 替换为 `snprintf` / `std::format`
- [ ] `strcat` → 替换为 `strncat` / `std::string`
- [ ] `system` / `popen` → 替换为 `fork`+`exec`

### 🔴 多线程环境禁止
- [ ] `strtok` → 替换为 `strtok_r`
- [ ] `strerror` → 替换为 `strerror_r`
- [ ] `gmtime` → 替换为 `gmtime_r`
- [ ] `localtime` → 替换为 `localtime_r`
- [ ] `ctime` / `asctime` → 替换为 `ctime_r` / `asctime_r`
- [ ] `rand` / `srand` → 替换为 `std::random_device` / `<random>`
- [ ] `gethostbyname` → 替换为 `getaddrinfo`

### 🟡 需注意
- [ ] `strdup` 返回值是否已 `free`？（隐式 malloc）
- [ ] `realpath` 是否使用缓冲区版本？
- [ ] `strtok`/`strsep`/`basename`/`dirname` 是否传入只读字符串？
- [ ] `errno` 是否在系统调用后立即读取？
- [ ] `setjmp`/`longjmp` 是否使用？（建议重构）

### 🔴 信号处理函数中禁止
- [ ] 是否有 `malloc`/`free` 调用？
- [ ] 是否有标准 IO 操作？
- [ ] 是否有非异步安全函数调用？

## 7. 并发安全（Concurrency）

### 🔴 必须检查
- [ ] 共享数据是否有锁保护？
- [ ] 是否有数据竞争（data race）？

### 🟡 建议检查
- [ ] 锁粒度是否最小？（不持锁做 IO/sleep）
- [ ] 是否有嵌套锁？（死锁风险，用 `std::lock()` 一次获取多锁）
- [ ] `mutable` 成员在并发访问时是否安全？
- [ ] `recursive_mutex` 使用是否必要？（通常说明设计需改进）
- [ ] 是否使用 `std::atomic` 进行原子操作？
- [ ] 是否有线程不安全的全局状态访问？

## 8. 现代 C++（Modern C++）

### 🟡 建议检查（现代C++核心）
- [ ] **类型推导**：是否正确理解模板类型推导的三种情况？（引用/通用引用/传值）
- [ ] **auto使用**：auto + 花括号初始化是否意外推导为 `std::initializer_list`？
- [ ] **decltype(auto)**：返回类型是否正确？是否返回了局部变量的引用？
- [ ] **智能指针选择**：独占资源用 `std::unique_ptr`，共享资源用 `std::shared_ptr`？
- [ ] **make函数**：是否优先使用 `std::make_unique`/`std::make_shared` 而非 `new`？
- [ ] **移动语义**：`std::move` 是否仅用于右值引用？`std::forward` 是否仅用于通用引用？
- [ ] **通用引用 vs 右值引用**：`T&&` 是否存在类型推导？（区分通用引用和右值引用）
- [ ] **移动操作陷阱**：移动操作是否声明了 `noexcept`？是否依赖不一定更快的移动？
- [ ] **Lambda捕获**：是否避免默认捕获 `[=]`/`[&]`？是否正确捕获 `this`？
- [ ] **Lambda vs std::bind**：是否优先使用 lambda 而非 `std::bind`？
- [ ] **并发模型**：是否优先使用 `std::async`（基于任务）而非 `std::thread`（基于线程）？
- [ ] **std::atomic vs volatile**：并发是否使用 `std::atomic`？`volatile` 是否仅用于特殊内存？
- [ ] **Pimpl惯用法**：使用 `std::unique_ptr` 的 Pimpl 是否在实现文件中定义了特殊成员函数？
- [ ] **override/noexcept/constexpr**：是否正确使用这些现代C++关键字？
- [ ] **完美转发失败**：花括号初始化、0/NULL、仅声明的static const成员是否导致转发失败？

### 🟢 可选检查
- [ ] 是否使用了 `constexpr` 替代宏定义？
- [ ] 是否可以使用 `std::array` 替代 C 风格数组？
- [ ] 是否可以使用 `std::optional` 替代 `nullptr` 表示无效值？
- [ ] 是否有 `auto` 可以使用但未使用？（提升可读性）
- [ ] 是否有范围 `for` 循环可以替代普通 `for` 循环？
- [ ] 是否使用了 C++20 `std::format` 替代 `sprintf`？
- [ ] 是否有 `std::string_view` 可以替代 `const std::string&`？
- [ ] 是否有 Concepts（C++20）可以替代 `static_assert`？
- [ ] 是否使用了 `nullptr` 替代 `NULL` 或 `0`？
- [ ] 是否有 `override` 说明符缺失？
- [ ] 是否有 `const` 成员函数可以使用但未标记？

## 9. 代码规范（Coding Standards）

### 🟡 建议检查
- [ ] 头文件是否有 `#ifndef`/`#define`/`#endif` 或 `#pragma once`？
- [ ] 头文件各部分书写顺序是否规范？（头文件说明 → 防重复包含 → Debug开关 → Include → 宏定义 → 结构体 → 函数声明）
- [ ] 源文件各部分书写顺序是否规范？（源文件说明 → Debug开关 → Include → 宏定义 → 结构体 → 声明 → 全局变量 → 静态变量 → 函数定义）
- [ ] 头文件和源文件命名是否合理？（小写字母，模块名缩写前缀）
- [ ] 目录结构是否清晰？
- [ ] 版权和版本声明是否完整？
- [ ] 一行代码是否只做一件事？
- [ ] 代码行最大长度是否控制在 80 字符以内？
- [ ] `if`/`for`/`while` 是否自占一行且加大括号？
- [ ] 缩进是否统一使用 4 个空格（不使用 Tab）？
- [ ] 修饰符 `*` 和 `&` 是否紧靠变量名？
- [ ] 命名风格是否一致？（类名/函数名/变量/常量）
- [ ] 变量命名是否可望文知意？（英文单词组合，不用拼音）
- [ ] 标识符是否避免仅靠大小写区分？
- [ ] 所有宏定义、枚举常数、只读变量是否全用大写字母命名？
- [ ] 静态/全局/成员变量是否有前缀区分？（g/n/f/a 等作用域前缀）
- [ ] 是否有同名局部变量和全局变量？
- [ ] 是否有数字编号变量名？（如 Value1, Value2，除非逻辑需要）
- [ ] 注释是否清晰且必要？注释是否与代码一致？
- [ ] 全局数据是否有注释？
- [ ] 注释是否注重"为何做"而非"怎么做"？
- [ ] 数值单位是否有注释？变量范围是否有注释？
- [ ] 文件头部是否包含修改记录？

### 🟢 可选检查
- [ ] 头文件是否过于庞大？（分解为更小的头文件）
- [ ] 模板元编程是否过于复杂？（添加注释或简化）
- [ ] 是否有过于复杂的嵌套 lambda？
- [ ] 是否有 magic number 需要定义为常量？
- [ ] 是否有 TODO/FIXME/HACK 未处理？

## 10. 函数设计

### 🟡 建议检查
- [ ] 参数书写是否完整？（不省略参数名，无参数用 void）
- [ ] 参数命名和顺序是否合理？（目的参数在前，源参数在后）
- [ ] 参数个数是否过多？（建议 ≤4，超过用结构体打包）
- [ ] 是否有类型和数目不确定的参数？（尽量避免）
- [ ] 返回值类型是否正确？是否省略？（无返回值用 void）
- [ ] 函数名与返回值语义是否冲突？（如 getchar 返回 int 非 char）
- [ ] 正常值和错误标志是否分离？（正常值用输出参数，错误用 return）
- [ ] 是否使用 `assert` 检查指针参数有效性？（入口校验）
- [ ] 是否使用 `const` 保护输入指针参数和返回值？
- [ ] 是否返回指向栈内存的指针/引用？
- [ ] 函数体是否控制在 80 行以内？
- [ ] 函数功能是否单一？（不设计多用途函数）
- [ ] 相同输入是否产生相同输出？（避免 static 局部变量的记忆功能）
- [ ] 是否检查了全局变量和文件句柄等非参数的有效性？
- [ ] 函数是否都有完整的头部注释？
- [ ] 函数之间是否有空行分隔？
- [ ] 变量定义和语句之间是否有空行？
- [ ] 是否使用了递归？（注意栈溢出风险和效率）

## 11. 类与对象

### 🟡 建议检查
- [ ] `public` / `protected` / `private` 顺序是否一致？
- [ ] 是否使用初始化列表？
- [ ] 多态类是否有虚析构函数？
- [ ] 构造/析构函数中是否调用虚函数？（禁止）
- [ ] `const` 数据成员是否被误解？（只在对象生存期内是常量）
- [ ] 类的职责是否单一？

## 12. 输入验证与注入防护

### 🔴 必须检查
- [ ] 所有外部输入是否经过验证和过滤？
- [ ] 输入长度、类型、范围是否限制？
- [ ] 是否存在未验证输入直接拼接命令/查询？
- [ ] 是否对特殊字符（`< > & " ' /`）进行转义？
- [ ] SQL 查询是否使用参数化查询？
- [ ] 文件路径是否规范化并检查目录白名单？

### 🟡 建议检查
- [ ] 是否有 XSS 防护？（输出 HTML 编码）
- [ ] 是否有 CSRF 防护？（Token 校验）
- [ ] 是否有反序列化注入风险？

## 13. 日志与错误处理

### 🔴 必须检查
- [ ] 日志是否记录密码等敏感信息？
- [ ] 错误信息是否泄露系统信息/堆栈/内部 IP？

### 🟡 建议检查
- [ ] 日志是否记录完整审计信息？（时间、IP、账号、操作、结果）
- [ ] 错误处理是否统一？
- [ ] 异常是否暴露技术细节？
- [ ] 是否有资源未释放的异常路径？（文件、连接、内存）
- [ ] 错误处理程序块本身是否正确？

## 表达式与控制流

### 🟡 建议检查
- [ ] 运算符较多时是否用括号明确顺序？
- [ ] 是否有过于复杂的复合表达式？
- [ ] 是否有多用途的复合表达式？（一个表达式做两件事）
- [ ] 是否有含否定运算的条件表达式？（`!(num>=10)` → `num<10`）
- [ ] 浮点变量是否直接与 TRUE/FALSE 或 1/0 比较？（禁止，用 EPSINON 精度）
- [ ] 指针变量是否与 NULL 比较？（用 `NULL == p`，避免 `p == 0`）
- [ ] `switch` 是否有 `default` 分支？
- [ ] `case` 结尾是否有 `break`？
- [ ] `case` 排列是否按字母/数字顺序或执行频率排列？
- [ ] `case` 后面的代码是否简洁（≤20行）？
- [ ] `case` 是否只用于整型/字符型常量？
- [ ] 是否有 `goto` 语句？（禁止）
- [ ] 是否将指针变量与布尔值直接比较？（用 `nullptr`）
- [ ] 循环嵌套是否超过 3 层？
- [ ] 循环体是否超过 20 行？
- [ ] 是否在循环体内修改循环变量？
- [ ] 多重循环中最长循环是否放在最内层？
- [ ] for 循环是否使用半开半闭区间？
- [ ] `if` 后面是否有多余的分号导致空语句？
- [ ] `else` 悬垂是否可能导致混淆？
- [ ] 是否有 `y = x/*p` 形式的注释误解析？（`/` 和 `*` 之间加空格）

### 🟢 预处理检查
- [ ] 宏定义是否用括号保护参数和整个表达式？
- [ ] 代码中是否有"魔鬼数"（应定义为宏或 const）？
- [ ] 是否有宏定义中不必要的空格导致定义错误？
- [ ] `#include` 路径是否正确？（`<>` vs `""`）
- [ ] 结构体内存对齐是否合理？（成员按大小排列减少填充）
