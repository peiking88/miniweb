# Per: Performance

## 1. 编码规范（行业经验版）

### 必须（MUST）
- **先测量再优化**：无基准数据的“优化”默认视为风险改动。
- **关注算法复杂度**：优先 O(n) vs O(n log n) 的选择，其次才是微优化。
- **避免不必要的动态分配**：
 - 优先栈对象/对象成员；
 - 容器提前 `reserve()`；
 - 避免在热点路径频繁创建线程/锁。

### 建议（SHOULD）
- 优先标准库算法与容器（更容易被优化、也更容易读）。
- 使用 move 语义、`string_view/span` 减少拷贝，但要保证生命周期。
- 临界区短小，减少锁竞争与上下文切换。

### 禁止（MUST NOT）
- 禁止“为了性能”牺牲安全与清晰（例如用未定义行为换速度）。

## 2. 走查清单（Checklist）

- P0：是否引入 UB/数据竞争作为“优化手段”？
- P1：是否存在明显的 O(n^2) 或重复遍历？
- P1：热点路径是否大量分配/拷贝/格式化/日志 IO？
- P2：是否应该用 `reserve`、避免临时对象、减少虚调用？

## 3. 推荐/不推荐

### 推荐（Good）
```cpp
std::vector<int> v;
v.reserve(n);
for (int i = 0; i < n; ++i) v.push_back(i);
```

### 不推荐（Bad）
```cpp
std::vector<int> v;
for (int i = 0; i < n; ++i) v.push_back(i); // 可能反复扩容
```
