# NR: Non-Rules and myths

## 1. 工程共识（行业经验版）

### 必须（MUST）
- **不要用绝对化口号替代工程判断**：例如“永远不用异常/模板/动态分配”。
- **用数据与风险驱动决策**：性能看基准，安全看 sanitizer/静态分析，架构看演进成本。

### 常见迷思澄清（示例）
- “异常慢”：在无异常路径上成本通常可控，关键是边界与策略。
- “shared_ptr 很方便”：方便但昂贵且易引入生命周期耦合/环。
- “用 unsigned 避免负数”：会引入隐式提升 bug（ES.100/106/107）。

## 2. 走查清单（Checklist）

- 是否出现基于迷思的规则（一刀切）导致代码更差？
- 是否缺少测量/验证就做结论？

## 3. 建议落地方式

- 允许例外，但必须记录理由与验证方式。
- 争议点（异常/RTTI/多态）以模块为单位统一策略，避免“每个人一套”。
