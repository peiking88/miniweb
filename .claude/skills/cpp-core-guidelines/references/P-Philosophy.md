# P: Philosophy

## 1. 编码规范（行业经验版）

### 必须（MUST）
- **表达意图优先**：代码首先服务阅读者，其次服务编译器。
- **把错误尽量推到编译期**：强类型、`constexpr`、`enum class`、`span`、`not_null`、概念/约束。
- **默认安全**：
 - 所有权清晰（RAII/智能指针）；
 - 避免未定义行为；
 - 并发默认无数据竞争。
- **资源管理一律 RAII**：内存/锁/文件/句柄一视同仁。

### 建议（SHOULD）
- **优先标准库与成熟抽象**，少写手工循环/手搓容器。
- **先测量再优化**（Performance 章节），避免“想当然优化”破坏可维护性。

### 禁止（MUST NOT）
- 禁止用“聪明代码”替代清晰代码（过度模板元编程、宏黑魔法、隐式行为）。

## 2. 走查清单（Checklist）

- 是否用类型/接口清楚表达所有权、可空性、范围与单位？
- 是否有隐藏的 UB/生命周期风险？
- 是否有不必要的共享可写状态？
- 是否重复造轮子而不是用标准库？

## 3. 推荐/不推荐（示例）

### 推荐（Good）
```cpp
// 强类型表达意图
enum class Mode { fast, safe };
void run(Mode m);
```

### 不推荐（Bad）
```cpp
// 用 bool/int 表达业务语义
void run(int mode); // 0/1/2 含义不清
```
